Замер реального объёма описаний инструментов `a1-mcp-server` и сравнение
двух стратегий диспетчеризации: «все инструменты всегда в контексте» против
«роутер (дешёвая LLM или эмбеддинги) сужает список до top-K».

Цифры токенов — **измерены по фактическому коду** (скрипт `analyze-tokens.mjs`),
стоимости — примерные рыночные цены за 1M токенов (уточняйте у провайдера).

## 3. Сравнение сценариев (стоимость схем за один ход)

| Сценарий | Механика | Стоимость/ход | Экономия vs A |
|---|---|---|---|
| **A** | все 54 схемы всегда в контексте | **$0.00374** | — |
| **B** | дешёвый LLM-роутер → top-5 схем | $0.00041 | 89% |
| **C** | эмбеддинги → top-5 схем | $0.00035 | 91% |

### Детали сценария B (LLM-роутер)

- Вход роутера: компактный индекс (имена + однострочники) ~400 ток. + промпт ~150 ток. = 550 ток.
- Выход роутера: список ~5 имён = 30 ток.
- Стоимость роутера: `$0.000067`.
- Main-модель получает только top-5 схем (~115 ток.) = `$0.000345`.

### Детали сценария C (эмбеддинги)

- Эмбеддинг запроса (~25 ток.) = `$0.0000025`.
- Main-модель получает top-5 схем (~115 ток.) = `$0.000345`.

## 4. Главный вывод (важно — он контринтуитивен)

Роутер/эмбеддинги формально дают **~90% экономии** на схемах, но **абсолютная
разница ничтожна** — доли цента за ход.

Причина: **схемы — самая дешёвая статья** реального расхода. Фактическую
стоимость хода определяют:

1. **Системный промпт** (обычно 1–3К токенов).
2. **История диалога** (растёт с каждым ходом, сотни/тысячи токенов).
3. **Результаты вызовов инструментов** — самый жирный кусок. Например,
   `a1_list_cubes` возвращает список кубов, который занимает больше токенов,
   чем все 54 схемы вместе.

Экономия 90% на самой маленькой статье теряется на фоне остального.

---

## 5. Когда эмбеддинги/роутер реально окупаются

- Инструментов **сотни/тысячи** (не 54), схемы суммарно — десятки тысяч токенов.
- Высокий скрытый риск: чем больше инструментов, тем выше вероятность, что
  LLM выберет не тот (особенно при похожих описаниях).
- Маленькое контекстное окно и/или дорогая модель.

**Эмпирический порог для нашего проекта:** примерно **200+ инструментов**,
либо когда суммарный объём схем превышает ~10К токенов (тогда ~$0.03/ход и
уже ощутимо).

## 6. Рекомендация для `a1-mcp-server` (54 инструмента)

- **Достаточно сделанного** `readonly`-гейта (27 инструментов, ~685 токенов).
- **Tool-filter клиента** — бесплатно оставить 5–10 нужных под задачу.
- **Эмбеддинги/LLM-роутер** — преждевременная оптимизация при текущем масштабе:
  дают 90% экономии на статье, которая и так стоит $0.0037/ход.

## Приложение: методология

- Токены схем измерены скриптом `analyze-tokens.mjs` (парсинг `server.tool(...)`
  из `src/tools/*.ts`, оценка ~4 символа/токен для латиницы, ~1.5 для кириллицы).
- Это оценка, а не точный `cl100k_base`/`o200k`-подсчёт — для относительного
  сравнения сценариев точности достаточно.
- Стоимости — приблизительные рыночные; подставьте прайс провайдера для
  точного бюджета.
